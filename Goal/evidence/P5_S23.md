## About the drive runs
Eleven runs were made while the script grew. The first three failed on the script itself (a stale status parser, a click on a tile cut off by the top of the grid, the number field keeping the focus after Escape); all were fixed in the script, not the app. Five later runs on the nearly final tree failed once each for reasons outside the app: an idle CPU reading of 3.4 % with the library open (a 0.0 to 0.9 % reading in the other runs), the popup opened elsewhere and the click fell outside it, the tile list was read before the first frame, a keystroke was lost and the library closed (a deactivation, which closes it like a menu), and a stray letter T arrived in the preview window. Other builders run desktop drives and tests on the same screen and keyboard (the CPU readings of two runs also jumped to 3 to 18 % while the preview was idle and closed), so these are treated as desktop crosstalk; the script now waits for the tile list before reading coordinates and counts presented frames for the idle check, and the clean runs are the evidence. Runs 4, 5 (earlier tree) and the last one on the final tree had 0 failures.

## Deviations and gaps
- The first opening of a session costs about 21 ms offscreen (glyphs, icons and the first 16 pictures are made then); later openings under 1 ms. On the real desktop the key to pixel time was 11 to 12 ms (with the first opening of the drive at 23 ms), which includes the display refresh.
- The Assets grid and the Actions list keep plain letters for their type-ahead, so B typed while they have the focus does not open the library (click the viewport or the Outliner first); documented in `docs/dev/brush-library.md` section 4.
- A popup in a very small floating window shows no key hints and no count (only the option).
- Not verified: another display scale, an IME, a keyboard layout whose B key produces a different character.
