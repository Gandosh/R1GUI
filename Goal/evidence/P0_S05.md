# Slice evidence: 0.5 Decide build system, C++ standard and compiler

**Status:** OWNER ACCEPTED
**Date:** 2026-10-09   **Risk tier:** Medium (shapes every later build and CI slice)   **Review:** none (owner decision)

## Decision
| Item | Choice |
|---|---|
| Build system | CMake with presets, Ninja generator |
| C++ standard | C++20 |
| Primary compiler | MSVC (Visual Studio 2022 or newer) |
| Second compiler | clang-cl, built in CI as a portability check |

Owner accepted the recommendation as proposed.

## Rationale
- CMake presets match the `build/<phase>` temporary-tree rule; works for Vulkan, shader compilation and later macOS/Linux ports.
- C++20 gives concepts, `std::span`, designated initializers and `constexpr` improvements useful for checked-size and handle code; C++23 adds little and has uneven support.
- MSVC is the Windows-first default with the best debugger/profiler; clang-cl catches portability bugs early.

## Left open, not decided here
- Shader compilation to SPIR-V (glslang or DXC) and vendoring vs vcpkg were raised alongside; they are finalized with the third-party allowlist in slice 0.7.

## Consequences
- Slice 0.11 creates the CMake skeleton and presets; 0.12 wraps builds in `tools/build` with a per-tree lock; 0.14 builds with MSVC and clang-cl in CI.

## Unresolved issues
- Exact minimum MSVC and CMake versions are set when the skeleton is created (0.11).
