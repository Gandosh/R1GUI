# Slice evidence: 3.12 Preview: themed window with a panel of static widgets

**Status:** TECHNICAL PASS (owner interaction pending; visual comparison with the reference does not yet meet the provisional tolerance)   **Date:** 2026-10-09   **Risk tier:** Medium (first integration of four separately built modules)

## What runs
- The preview is rebuilt on the Phase 3 stack: a borderless window with a 32 px title bar drawn by the toolkit (app title, mode name, four mode squares, minimize, maximize and close buttons with hover and pressed states; caption drag, double-click maximize, edge resize), one render device, a window target and the painter for everything. The older modes (token swatches, reference screens, docking sandbox) are re-implemented on the painter with the same behavior.
- New default mode, Widgets: a themed properties panel for a selected rectangle (header, Position, Layout, Appearance, Fill, Stroke, Effects, Export) built from the widget tree, flexbox layout, style table and tokens; text shaped by the text module and drawn from the glyph atlas (uploaded as an R8 texture, dirty rectangles only); icons drawn by a small SVG-subset rasterizer written for the preview (all 156 extracted Lucide icons parse and draw; it is not the final icon pipeline); hover feedback and cursor shapes through the router; a real editable Name field (typing, selection by keyboard and mouse, copy, cut, paste, undo, caret blink).
- Frames are drawn only when something changed; an idle preview blocks on events. Dark and light with T; Tab cycles Widgets, Swatches, Screens, Sandbox; Esc leaves the Name field, cancels a dock drag or quits.

## Builder's verification (reported, not all re-run by me)
Real-mouse drive with screenshots: hover on fields (lighter background, resize cursor), hover on the close button (red), typing, selection, paste and undo in the Name field (a typed letter did not toggle the theme), swatches and screens modes, sandbox tab drag with drop outline, resize while dragging (content re-lays-out live: 1280x800 to 780x500 to 1680x1000), minimum size clamp (320x200), caption drag moved the window by exactly the requested offset, maximize and restore, caption double-click, minimize (0.016 s CPU over 3 s), restore, Esc cancelling a dock drag during a resize, clean close. Debug runs with the validation layer printed no validation messages (stderr held only the line naming the chosen GPU).

## Visual comparison with the reference (honest numbers)
Offscreen render of the panel at 1440x900, cropped to the right-panel region and compared with `screen-rectangle-selected.png` through `tools/spec/imgdiff.py --profile screen` (limit 3% failing pixels): dark 5.5% failing (max difference 194, mean 5.2), light 6.1% (mean 6.5); excluding the 40 px strip that deliberately differs: dark 3.8% (mean 3.4), light 4.7% (mean 4.4). Both fail the provisional limit. Geometry matches within a pixel (section tops, 26 px rows, 114 px half fields; asserted in scene_test). Visible differences: the reference text is heavier (browser gamma and contrast; the synthetic bold strength was boosted 2.0x by eye and is not final), the nested-diamond icon is a plain diamond, icon stroke weights differ slightly. Hover colours were not compared against the reference.

## Deliberate deviations from the reference panel
The Design/Code/AI/100% strip is replaced by a segmented control (Design | Code) and the Name field; the header title is 12 px semibold instead of the specified 13 px because that matched the measured width.

## Changes made outside the preview
Window: `waitForEvents` and a live callback that fires during Windows' own move/size loop (so rendering continues while dragging); the cursor now applies immediately. Renderer: `memoryUsage()` via VK_EXT_memory_budget and per-frame timings. A doc fix in the painter header (the uv rectangle is origin plus size). New tests for each. Executables now reserve an 8 MiB stack (top-level CMake).

## Not verified
Device-lost recovery, DPI other than 100% on a real display (only layout at 150% in a test), the Windows 11 snap-layout flyout, hover colours against the reference, and the light theme beyond a few screenshots.

## Owner interaction checklist
1. `tools/run/preview.cmd`: the window opens with our own title bar and the properties panel on the left.
2. Move over the fields (lighter background; resize cursor on number fields, text cursor on the Name field). Type in the Name field; select with Shift+arrows or the mouse; Ctrl+C, Ctrl+V, Ctrl+Z.
3. Press T for light and dark (with focus outside the Name field), Tab for the other modes (four squares at the top right show which).
4. Drag the title bar, drag the window edges (the panel re-lays-out), double-click the title bar, use the three title-bar buttons.
5. Scroll the panel with the mouse wheel.
