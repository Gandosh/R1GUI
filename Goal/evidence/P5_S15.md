# Slice evidence: 5.15 Custom menu model: pie menu and dockable menu, validated and persisted

**Status:** TECHNICAL PASS (owner interaction pending)   **Date:** 2026-10-10   **Risk tier:** High (serialization, public API)   **Review:** none yet

All GPU work ran on the RTX 4080.

## Built
`CustomMenuSet`, `CustomMenuStorage`, `CustomMenuCommands`, `CustomMenuPanel` (guide `docs/dev/custom-menus.md` sections 1 to 6). Slice 5.19 integrated them: the preview loads and saves `custom-menus.json` (atomic, damaged file kept aside), registers one dock panel per dockable menu (panel id 1000 + serial, registered before the layouts start so a stored layout restores them), and registers the commands behind the **Custom Menus** main menu (last of the eight top-level menus, rebuilt from a timer with `Customization::setBuiltin`).

## Verification
- `preview.editor`: first-run samples (Tools Pie, Quick Tools), menus listed, commands registered, a dockable menu created, its panel opened, closed and opened again from its command, menus and open panels surviving a restart, a damaged `custom-menus.json` kept aside, deleted menu removes its commands.
- Real desktop: the sample panel on the first start, a created panel opening in the dock, close with Ctrl+W and reopen from Custom Menus, restart brings every menu and panel back (`menus_drive.ps1`, 0 failures).
- **Defect found while integrating (host contract):** `CustomMenuSet` notifies a copy of its listener list, so a host that closes a dock panel inside the notification destroys the panel while its listener is still going to be called (exception "parent widget does not exist"). The preview now only touches the panel registry inside the notification and closes panels and rebuilds the menu bar from a timer. Documented in `docs/dev/preview.md` section 5.

## Not implemented / gaps
`PanelRegistry` cannot remove a panel: a deleted dockable menu's panel is closed and stays registered unused (ids are never reused because serials are not).
