# Slice evidence: 3.2 ui-render: Vulkan device, swapchain per window, frame loop

**Status:** TECHNICAL PASS   **Date:** 2026-10-09   **Risk tier:** High (GPU lifetime, synchronization)   **Review:** no independent review yet (recommended at phase close)

## Built
- Shared RenderDevice (validation in Debug, explicit GPU selection by index, name or the R1UI_GPU variable, chosen GPU logged, deferred destruction driven by a timeline semaphore, device-lost mapped to a clear error), one WindowTarget per window (resize, out-of-date and suboptimal recreate, minimized skip, frames in flight, FIFO with a mailbox or immediate request), an OffscreenTarget with readback for tests, Texture objects (R8 coverage, RGBA8) with staged subregion updates, and a beginFrame/endFrame frame API. Colours are sRGB-encoded values blended in encoded space (matches browser rendering), premultiplied output.
- The older Renderer and FrameContent API is re-implemented on top of the new classes with identical observable behavior.

## Verification
- Fast tier 13 of 13 and GPU tier 15 of 15 pass in Release and Debug (validation layer on, 0 messages; the programs exit non-zero on any validation message). I re-ran the GPU tier on the merged tree through the RTX 3090: 15 of 15 passed.
- window_lifecycle creates and destroys a window target 200 times and rebuilds a swapchain 200 times; multi_window renders two windows from one device. A first Debug run exposed incompatible render passes (validation message); fixed with identical subpass dependencies.
- The existing docking sandbox rendered through the new path is pixel-identical to the previous build apart from OS title-bar rows (max channel difference 2).

## Not verified and gaps
- A real device-lost event (only the mapping exists), real interactive resize and minimize, mailbox and immediate present beyond the fallback check, multi-monitor and DPI, the RTX 4080 (all runs used the 3090), and the 4096-texture limit.
- Swapchain recreation does one wait-idle, which briefly stalls all windows during a resize (documented).
