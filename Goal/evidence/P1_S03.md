## Method
Storybook could not be used: the OpenPencil checkout has no node_modules and installing it needs downloads. The built app in `reference/OpenPencil/dist` is served locally and driven by `tools/spec/capture.mjs` through headless Chrome (DevTools protocol, Node built-ins only, viewport 1440x900, device scale 1, sRGB, software GL). Command:
`node tools/spec/capture.mjs reference/OpenPencil/dist tests/reference/openpencil docs/spec/measurements.json`

## Output (tests/reference/openpencil/, 1.6 MB)
- 100 PNGs plus `manifest.json` (theme, name, clip, viewport, source commit dd3161e44).
- Per theme (dark, light): 9 full-screen scenes (`screen-*`: empty or rectangle selected, File menu, select open, fill popover, color picker, context menu, toolbar tooltip, number field editing) and 40 widget crops (`widget-<name>-<idle|hover|focus>`) for 20 widgets.
- Consistency checked by `tools/spec/assets_check.py` (every manifest entry exists, decodes and matches its clip size).

## Verified by eye
Dark and light full screens and the color picker screen were viewed and show the expected UI.

## Gaps
- The dark set has `screen-empty`; the light set starts from the rectangle-selected state (`screen-empty-canvas-selected`).
- Widgets not visible in the default document (switch, dialog, toast, document tab bar, gradient editor) are not captured; hover states are captured, pressed and disabled are not.
- Rendering uses Chrome with software GL and Skia text; anti-aliasing can differ from a GPU machine by small noise (covered by the provisional tolerances).
- No Storybook screenshots as originally worded; the real app is the stronger reference.
