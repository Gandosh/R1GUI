# Slice evidence: 3.6 ui-core: retained widget tree with generation-checked handles

**Status:** TECHNICAL PASS   **Date:** 2026-10-09   **Risk tier:** High (stale handles)   **Review:** no independent review yet (recommended at phase close)

## Built
- WidgetId with index and generation (generation 0 is never issued) over an arena: create, destroy subtree, reparent (a move under itself or a descendant is refused), reorder siblings, find, safe iteration while mutating (iterates an id snapshot), mutation lock during layout. Limits: depth 256 by default (hard cap 512 after a 1024-level test overflowed the 1 MB stack), 1,000,000 nodes. Per-node flags and a 64-bit user slot.

## Verification
- ui-core.tree: 74 checks including stale ids after destroy and slot reuse, destruction during iteration, deep trees, 100k nodes (create, walk, destroy and reuse in about 100 to 115 ms), reparent into own descendant refused.

## Not verified and gaps
- Debug-build stack use at the 512-level cap and layout on a non-main thread's stack were not tested.
