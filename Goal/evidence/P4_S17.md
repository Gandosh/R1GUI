## Integration bugs found and fixed (tests in `tests/ui-widgets/runtime/integration_test.cpp`, `tests/preview/modes_test.cpp`)

1. Focusing from outside a dispatch frame could free a widget whose blur handler destroys it: `UiContext::focusWidget(id, reason)` and `clearFocus()` run guarded (test: object still alive after the handler's destroy).
2. Typing "t" in any text widget triggered the application's theme shortcut (the global key handler saw unhandled letter keys): `WidgetObject::wantsTextInput()`, overridden by TextInput, NumberField, Select, SelectList, PickerEntry, MenuPanel, ThumbnailGrid and (while renaming) TreeView; `UiContext::onGlobalKey` withholds unmodified letters, digits and space from the shortcuts then.
3. `OverlayHost` border (1 px) was not part of its padding, so Menu, Select, FlyoutList, Tooltip, Popover and Dialog each added a 1 px margin: the host padding now includes the border, the six workarounds are removed, `Popover` adds its padding on top. `overlay_test` expectations changed to the consistent geometry; every visual test number is identical before and after (310 comparison lines compared, 0 differences).
4. Tab as mode switch versus focus navigation: Tab cycles modes only when nothing is focused and no popup is open (dialogs need Tab for their focus trap); Ctrl+Tab always cycles.
5. Benchmark harness: `settle()` never ends while a field blinks its caret; the focused-field idle run steps a fixed number of frames instead.

## Not done / limits

- Rotation is edited and stored but not drawn (Painter has no rotated rectangles); no document-level undo (the Name field has its own); selecting another layer keeps the panel on the rectangle; the Code tab and Assets tab show a toast.
- The caret blink of a focused field renders continuously (about 33 % of one core on this machine); a timer-driven blink would fix it.
- Seen once, not reproduced: in the first benchmark run (3090, before the overlay change) the 30 s idle after blurring the Name field showed 3203 frames; the final runs on the 4080 show 0 frames after blur (also asserted headless in `modes_test::testIdleAfterFocus`). Cause unknown; the number should be watched in the next baseline.
- Modifier chords cannot be posted by the scripted driver (no Ctrl+Z, Ctrl+Tab run in the GUI).
