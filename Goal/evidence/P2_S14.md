# Slice evidence: 2.14 Preview: docking sandbox

**Status:** TECHNICAL PASS (owner interaction pending)   **Date:** 2026-10-09   **Risk tier:** Medium (new module and window input API; no independent code review yet)

## What was built
- New module `source/ui-dock` (headless): dock tree of splits and tab stacks with weights, floating areas as rectangles in the same space, drop-zone hit test, dock, close, activate, splitter move with a configurable floor (default 20 px), proportional resize through weights, versioned JSON persistence with full validation (a rejected layout leaves the caller's layout untouched), normalisation after every operation, panels the host no longer has are dropped. Plus a JSON writer in `ui-core`.
- Window input: mouse button, move and capture-lost events, cursor shape, S/L/R keys (existing queues unchanged).
- Preview mode 3 (Tab cycles swatches, reference screens, sandbox): 9 panels in a default layout (2 left, 2 centre, 3 right, 2 bottom) drawn as colored rectangles with tab strips. Drag a tab (5 px threshold): a ghost follows the pointer and an orange outline shows the drop zone; release docks it. Drag splitters. Middle-click a tab closes it. Esc during a drag floats the tab. S saves `layout.json` next to the exe, L loads it (invalid file keeps the layout and says why in the title), R resets.

## Built from the specs only
Specs 02, 04, 05 and 08 (drag threshold, zones 30% of the panel clamped 5 to 150 px, 0.75 s hover-activate not modelled in the sandbox). Changes made to the specs during review were passed on and applied: no centre drop target (the body floats the tab), Escape floats the tab, splitter floor 20 px, tab width includes the overlap.

## Not built or not verified
- Not covered by tests: reopening a closed tab at its old slot, context menu actions, sidebars, panel kinds across windows, delayed auto-save, named layouts, import and export, fixed-content regions, toolbar overflow, double-click behaviors.
- No explicit collapse gesture and no minimum tab width (tabs shrink without a floor); window sizes are in physical pixels (no DPI scaling).
- Floating areas are rectangles inside the preview window, not native OS windows (slice 5.2). A drag that joins a tab strip has unit tests only, no screenshot.
- Real mouse hardware was not used; the drive used posted window messages and screen positions.

## Owner interaction checklist
1. `tools/run/preview.cmd`, then press Tab twice to reach the docking sandbox (title says "Docking sandbox").
2. Drag a tab from one strip to the edge of another panel: an outline shows where it will land; release to dock.
3. Drag a tab onto another strip's tab area to join it; drag one onto the middle of a panel body or out to empty space to float it. Press Esc during a drag: the tab floats.
4. Drag the thin bars between panels to resize; shrink a panel until it stops at the minimum size.
5. Middle-click a tab to close it. Press S, then rearrange, then L: the saved layout returns. Press R to reset.
