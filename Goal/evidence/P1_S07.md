# Slice evidence: 1.7 Preview: token and reference-screenshot viewer

**Status:** TECHNICAL PASS (owner interaction pending)   **Date:** 2026-10-09   **Risk tier:** Medium (new public renderer API, GPU resource lifetime, new parser at a file boundary)   **Review:** none yet (recommended at phase close)

## What was built (all from real toolkit modules)
- `ui-core`: JSON parser (`Json.h`, `src/Json.cpp`): never throws, returns an error with byte offset; limits depth 64, 16 MiB, 1M nodes; duplicate keys rejected; strict UTF-8 and surrogates. `ui-core` is now a static library.
- `ui-theme` (new): `Tokens` loader for `assets/theme/tokens.json`; validation without partial state; light colours matched to dark by name.
- `ui-platform`: key and left-click event queues (256 events, oldest dropped); no OS types in the public header.
- `ui-render`: `FrameContent` (clear, solid rectangles, one letterboxed image), `uploadImage` / `destroyImage` with generation-checked ids, RAII GPU buffers and images (`GpuResources`). No shaders or pipelines yet: rectangles are blitted texels, so rectangle alpha is ignored (documented; the 2D batcher in 3.3 replaces this).
- `examples/preview`: Phase 1 viewer. Mode 1 token swatches (hover shows the colour name and hex in the title), mode 2 the 9 reference screens per theme. The build copies `tokens.json` and converts the reference PNGs to `.r1img` next to the exe.

## Hostile-input coverage
JSON: empty, truncated, trailing comma, trailing garbage and NUL, 100,000-level depth bomb, bad escapes, lone surrogates, invalid UTF-8, `1e999`, leading zeros, BOM, size and node limits. Tokens: missing themes, mismatched key sets, bad hex, wrong types, duplicate names, truncated and missing files.

## Guard register rows touched
Integer narrowing (checkedCast on sizes), GPU lifetime (device idle before destroy, in-flight fences waited in `destroyImage`, staging memory freed before return), use-after-free (generation-checked ImageId), file/serialization security (JSON limits, tokens validation, raw image header validation), input queues bounded.

## Not verified
- Real mouse hardware hover and clicks (tests drove window messages); minimize/restore was exercised by the implementation run, not repeated here.
- Behavior with the RelWithDebInfo exe under the validation layer (validation is only loaded in Debug).
- Alpha-blended rectangles (not supported yet), DPI changes, multi-monitor.
- No independent review of the new renderer API; recommended before Phase 3 builds on it.

## Owner interaction checklist
1. `tools/run/preview.cmd` (builds `dev` and launches).
2. Mode 1: move over the swatches; the window title shows `<theme>: <name> <hex>` and the swatch gets a blue outline. Press T: dark and light palettes swap.
3. Press Tab: the reference screens appear fitted to the window. Left/Right (or click the left/right half) steps through the 9 screens, wrapping; T swaps the dark and light sets.
4. Resize the window and minimize/restore: it keeps rendering. Esc or the close button exits.
