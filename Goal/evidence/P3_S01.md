# Slice evidence: 3.1 ui-platform: Win32 window, input, clipboard, cursors, DPI; borderless windows with our own title bar

**Status:** TECHNICAL PASS (snap layouts, edge snapping, shadow and mixed-DPI moves unverified)   **Date:** 2026-10-09   **Risk tier:** Medium (OS boundary, input queues)   **Review:** no independent review yet (recommended at phase close)

## Built
- Borderless windows (frame removed, resize border and snapping kept, 1 px DWM shadow margin); caption, minimize/maximize/close and resize-band regions supplied by the toolkit through a hit-test description; chrome buttons act on release over the same button; maximized client fills the work area with no clipping. Native frame stays the default; tool-window flag for floating panels; several windows on one thread each see only their own events.
- One ordered, bounded event stream (key down/up with scancode and modifiers, character input as code points with surrogate pairs combined and control characters filtered, mouse with buttons, double-click, wheel with fractional deltas, focus, resize, move, DPI change, close request, capture lost); the older queues keep working. Per-monitor-v2 DPI with logical/physical helpers, ten cursor shapes, UTF-8 clipboard (invalid UTF-8, NUL and over 16 MiB rejected, previous content kept, short retry on contention), monitor enumeration and the visible-margin clamp rule (100 logical px).

## Verification
- Fast tier: platform tests link, utf, queue_dpi, monitor_clamp and chrome_hit pass (merged tree: 31 of 31 fast tests pass).
- Desktop tier: window_desktop passes (it skips itself without an interactive desktop): styles, hit-test results for caption, buttons and eight resize zones, key, char, mouse, wheel, focus, DPI and close events, a 5000-message flood within queue bounds, two windows, clipboard round trip with hostile text, hostile window descriptions.
- Real desktop run of the manual harness with the real mouse: hover zones reported correctly, caption drag moved the window, edge and corner drags resized, shrinking stopped at the 360x200 minimum, maximize and restore worked, maximized client 3440x1392 with nothing clipped, the tool window had no taskbar style.

## Not verified and gaps
- The Windows 11 snap-layout flyout, drag-to-edge snapping, the DWM shadow (PrintWindow does not capture it), the auto-hide taskbar edge, mixed-DPI multi-monitor moves and the caption double-click on a real desktop were not verified.
- The event pump does not return while Windows runs its own move or size loop, so rendering freezes during a drag unless redrawn from a timer or size callback (handled in the integration slice 3.12).
