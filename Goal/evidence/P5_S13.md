# Slice evidence: 5.13 Action list: searchable, draggable list of actions with a description on every row

**Status:** TECHNICAL PASS (owner interaction pending)   **Date:** 2026-10-10   **Risk tier:** Medium   **Review:** none yet

All GPU work ran on the RTX 4080.

## Built
`ActionList` / `ActionListView` (`source/ui-widgets/.../actions`, guide: `docs/dev/hotkeys.md` section 1): grouped, virtualized, searchable (name, id, description, category), a description on every row, drag payload `DragPayload::Kind::Command`. Slice 5.19 uses it three times: the right-hand list of the Create Custom Menu window (drag source), the preview's **Actions** panel (Enter or double-click runs the command) and inside the hotkey editor. The preview test asserts `commandsWithoutDescription(registry)` is empty (every Editor command, also the ones of the custom menu commands, explains itself).

## Verification
- Fast: `action_model_test`, `action_list_test`, `action_hostile_test`; GPU: `action_list_visual_test`; the creator tests drag real rows with pointer events.
- Real desktop (`tests/preview/menus_drive.ps1`): rows dragged with the real mouse from the action list of the creator window onto pie slots and into the panel preview, search typed with real keys.
- **Defect found by the desktop drive and fixed:** the search field "committed" when it lost the focus, and the list activated the selected action on every commit, so pressing a row to drag it (which takes the focus from the field) also added that action to the first free slot. A commit with a mouse button held is now ignored. Regression test in `action_list_test` (a press on a row after typing in the field activates nothing).

## Not implemented / gaps
No auto-scroll while dragging near the list edge; the first Escape in a text field of a dialog only drops the selection (a toolkit-wide TextInput behaviour).
