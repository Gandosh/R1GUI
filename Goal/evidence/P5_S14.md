# Slice evidence: 5.14 Hotkey editor like Maya: action list plus keyboard view with assigned keys

**Status:** TECHNICAL PASS (owner interaction pending)   **Date:** 2026-10-10   **Risk tier:** Medium   **Review:** none yet

All GPU work ran on the RTX 4080.

## Built
`HotkeyEditor` (`docs/dev/hotkeys.md` section 2) replaces the old Shortcuts panel of the preview (owner request): panel 9 is now the "Hotkey Editor". Edit > Hotkey editor... (Ctrl+K, Ctrl+S, also Help) opens it as a **native window of 1100 x 640** (the dock keeps the size of the region a tab leaves, so the host sizes the window after floating it; at 562 px the editor falls back to the stacked layout, whose caption lines overlap: a layout defect of the editor in narrow windows, not fixed here). Hotkey sets are saved by the host to `<data>\hotkey-sets\<name>.json` and restored when the editor is built; Import and Export use the file path dialog (`<data>\keybindings\`).

## Verification
- Fast: `preview.editor` opens the panel, selects Move, assigns M through the editor API (Assigned), saves a set (file written), keybindings.json written.
- Real desktop (`menus_drive.ps1`, step 7): Ctrl+K, Ctrl+S opens the editor in a native window; click in the search field, type "move", click the Move row, **click the M key on the drawn keyboard**: the status line reads "Assigned M to Move (primary)", keybindings.json holds the binding, after closing the window the key M selects the Move tool and **after a restart it still does** (capture `12_hotkey_editor_assigned.png` viewed: the M key is lit and its tooltip reads "M: Move").
- Gallery page "Hotkeys" registered in the preview.

## Not implemented / gaps
No numeric keypad or punctuation bindings (the toolkit's `Key` has none); no delete or rename of hotkey sets; set names are used as file names after replacing characters other than letters, digits, space and `_-.()` with `_`, so such a name returns with the replaced characters after a restart.
