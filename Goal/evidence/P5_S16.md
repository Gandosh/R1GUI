# Slice evidence: 5.16 Pie menu: hold the right mouse button, flick toward a slot

**Status:** TECHNICAL PASS (owner interaction pending)   **Date:** 2026-10-10   **Risk tier:** Medium   **Review:** none yet

All GPU work ran on the RTX 4080.

## Built
`PieGesture`, `PieMenu`, `PieTrigger` (`docs/dev/custom-menus.md` section 4). The preview wraps the viewport in a `PieTrigger` whose provider returns the pie created, edited or loaded last (the sample **Tools Pie** on the first start; the id is remembered in `viewport-pie.txt`). The Editor's global key handlers (main window and native windows) end a running gesture on Escape (`PieTrigger::cancelGesture`), also before the pie is drawn.

## Verification
- `preview.editor`: a synthetic right-button hold in the viewport draws the pie, moving up highlights slot 0, release runs its command; a second hold cancelled by Escape runs nothing.
- **Real desktop with the real right mouse button** (`menus_drive.ps1`, step 2): hold in the viewport, the pie is drawn (capture `02_pie_up.png`: eight slots, Move highlighted with the accent line), flick up runs Move, flick right runs Scale, a quick click runs nothing, Escape during the hold cancels. After creating a new pie the viewport uses it (flick right runs Rotate from the new pie).

## Not implemented / gaps
Only the viewport opens a pie; with several pies the viewport uses the last created, edited or loaded one (no "use in viewport" entry); a slot whose command is disabled (Undo with nothing to undo) is drawn dim and never chosen.
