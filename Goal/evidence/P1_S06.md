# Slice evidence: 1.6 Pixel-comparison method

**Status:** TECHNICAL PASS (tolerances provisional)   **Date:** 2026-10-09   **Risk tier:** Low

## Method
`tools/spec/imgdiff.py <reference.png> <candidate.png> [--profile name] [--diff out.png]`: images must have the same size; a pixel fails when any of R, G, B differs by more than `channelTolerance`; the comparison passes when the failing fraction is at most `maxFailingFraction`. It reports failing pixels and fraction, max and mean channel difference and the failing bounding box, and can write a red-on-dimmed diff image. Exit 0 pass, 1 fail, 2 input error.
Profiles in `tests/reference/tolerance.json`: default (8, 0.2%), flat (2, 0%), text (48, 3%), icons (32, 2%), screen (32, 3%). PNG reading and writing uses `tools/spec/png.py` (standard library only; validates signature, chunk sizes, filters and dimensions).

## Provisional
The text, icons and screen tolerances are estimates until real toolkit output exists. Phase 4 calibrates them against the first rendered widgets and records the final numbers here. Tightening or loosening changes what counts as a pass, so changes are reported to the owner.
