**Status:** TECHNICAL PASS   **Date:** 2026-10-09   **Risk tier:** Low

## Output
`assets/theme/tokens.json`, generated by `python tools/spec/build_tokens.py` (reproducible; reads OpenPencil `src/app.css`, its compiled CSS and `docs/spec/measurements.json`).
- `themes.dark` and `themes.light`: 34 colours each, identical key sets, all `#rrggbb[aa]` (checked by `tools/spec/assets_check.py`, CTest `spec.assets_consistency`).
- `palette`: 21 Tailwind colours the UI uses, converted from oklch to sRGB (for example red-500 = #fb2c36).
- `space`, `radius`, `font` (Inter, size and line-height scale, weights, tracking), `shadow` (Tailwind sm to 2xl plus overlay), `motion` (150 ms, ease 0.4/0/0.2/1), `widget` (sizes per widget), `measured` (rects and fonts measured in the running app).

## Notes and limits
- Values come from the compiled CSS, so tokens the build never uses (for example `panel-secondary`, `border-strong`, `danger`, `primary`) are absent or undefined in the reference. The widget code that references them (focus ring `primary`, invalid border `danger`, switch hover `border-strong`) has no defined colour in OpenPencil itself. The toolkit must choose values for those: open item for Phase 3 theming.
- The `widget` section is hand-transcribed from the theme definitions and cross-checked against measurements for the widgets that were captured; uncaptured widgets (switch, dialog, toast, tab bar) are source-derived only.
- Tokens are visual values only; OpenPencil is MIT (notice in docs/third-party.md).
